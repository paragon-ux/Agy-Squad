# `swarm-governance`: Native `/swarm` Execution Modifier

Use `swarm-governance` whenever running a multi-agent team on Antigravity native `/swarm`. It is an **Execution Modifier** that pairs with any Task Spec ([`pr-review`](pr-review.md), [`full-review`](full-review.md), [`self-diagnosis`](self-diagnosis.md), or opt-in flat [`day-one-review`](day-one-review.md)) to add scoped file boundaries, tiny receipts, dual-verdict integrity checks, and clean teardown on top of Antigravity's native board.

## Workflow stages

1. **Step 0: Fast missing-settings intake (`Coordinator`):** Read only the active `SKILL.md` entry file(s) and run `swarm{action: "models"}` (skipping upfront reads of reference docs or prior review ledgers) so intake completes in 1-2 turns. Check whether the user's swarm prompt specifies all four settings: **topology** (`flat` vs. `layered`), **model** (coordinator model vs. explicit pinned model), **workspace isolation** (`inherit` vs. `share`/`branch`), and **report retention** (`--prune` vs. `--keep-reports`). Trigger a single `ask_question` call **iff ANY** of the four settings is absent, asking **only** for the missing ones (recommended defaults: `flat` for inline tasks / `layered` for manifests with leads, coordinator model, `inherit`, `--prune`, plus an independent Integrity Audit); skip Step 0 only when all four are explicitly provided. In `squad_planner`, inline tasks default to `flat` while manifests with `lead` blocks compile `layered` unless `--topology flat` is passed.
2. **Stage 1: Plan, launch & park (`Coordinator` -> `Specialists` + optional `monitor` / `narrator`):** Call `squad_planner` (or `agy-squad plan`) to compile `swarmAdd` payloads, check writable `scopeFiles` overlaps, pin models, and emit `verificationPipeline` commands. Spawn workers via `swarm{action: "add"}`, verify active model IDs via `swarm{action: "status"}`, emit verbatim `open_board` on its own line on launch turns (and on resume turns or when asked while active), and park quiet turns with `swarm_wait` (no `schedule` polling timers). In layered cohorts, domain leads park immediately on `swarm_wait` without pre-reading repo files until specialist receipts arrive.
3. **Stage 2: Slot reports, content gate & flat integrity audit:** Each specialist writes evidence to `scratch/agy-squad/squad-<id>/specialist-<N>/report.md` and posts one single-line `<= 500` UTF-8 byte pointer (`@lead READY <slot> -- <observation>` or `@lead [done] READY <slot> - <observation>`, accepting optional leading `@mention` + `[done]` prefixes and spaced ASCII ` - ` or ` -- ` alongside ` — `) on the board. The lead or coordinator collects isolated slots (`agy-squad collect`), scopes board reads with `read_board{since|seqs}`, reads specialist reports first and spot-checks cited `file:line` claims and checks, writes `lead/report.md` (`Content Verdict: PASS | FAIL | BLOCKED`), and runs `agy-squad verdict` + `bundle-init --from-scope --digest` (or explicit `<verified-files...>`). Unless `--no-integrity` is set, an independent flat `audit-<id>` worker audits execution traces in two parallel turns (reading native `~/.gemini/antigravity*/brain/<id>/.system_generated/logs/transcript.jsonl` and `transcript_full.jsonl` directly standalone, or running `agy-context transcript list --parent <coordId> --lineage --json` + `health` followed by `outline --id <uuid> --full --out ...` and targeted `step` calls when optional `Agy-Context-Saver` `2.1.2+` is installed, where transcript access defaults to `OPEN` and operators can opt into `[agy-transcript-access: allow|deny]` on line 1 of worker prompts or via `agy-context transcript access`) to emit `Target Squad`, `Evidence Digest: <64-hex>`, and `Integrity Verdict: CLEAN | INTEGRITY VIOLATION`.
4. **Stage 3: Finalize, synthesize deliverable, prune, resume, or close:** Run `agy-squad verdict --integrity` and `agy-squad finalize <record.json> [--strict-citations]` **without `--prune`** first (or when planned with `--no-integrity`, skip `verdict --integrity` and run `agy-squad finalize <record.json> --allow-unaudited [--strict-citations]`) so verified bundle SHA-256 hashes are ready while loose specialist reports remain readable on disk. Next, synthesize all verified `lead/report.md` outputs into one complete user-facing deliverable (or single-pass durable ledger) using the verified bundle hashes: in layered mode, open raw `specialist-N/report.md` only when `citations.uncarriedUrls` is non-empty, a verdict is non-`PASS`, or specific raw evidence is needed; in flat mode, synthesize directly from `specialist-N/report.md`. Finally, if report retention is `--prune`, run `agy-squad prune <bundle.sources.json> <sha256>` (or `verify <bundle> --prune --expected-sha256 <sha256>`); single-step `finalize --prune` remains available when no bundle hash needs to be embedded before pruning. Lead the final response with the deliverable and keep verdicts, bundle SHA-256 digests, prune counts, and runtime closure in a compact verification footer rather than returning governance telemetry alone, skipping duplicate closeout test reruns on read-only runs when `git status` is clean on the already-tested `HEAD`. Post `[done] <summary>` (no `@`) before pausing with waiting workers or closing so `monitor`'s `*/3` cron cancels cleanly. Resuming a paused swarm cascades top-down (`coordinator -> leads -> workers` in layered mode, or `coordinator -> workers` in flat mode) using a plain resume prompt (`resume your assigned work from where you left off`) and re-emits verbatim `open_board` on its own line on the resume turn (and when asked while active). On close, kill all workers plus `monitor` (`swarm{action: "kill"}`) and complete the [four-check runtime closure gate](../roles-and-workflows.md#3-runtime-closure-checklist-and-hook-boundary).
