# `swarm-governance`: Native `/swarm` Execution Modifier

Use `swarm-governance` whenever running a multi-agent team on Antigravity native `/swarm`. It is an **Execution Modifier** that pairs with any Task Spec ([`pr-review`](pr-review.md), [`full-review`](full-review.md), [`self-diagnosis`](self-diagnosis.md), or opt-in flat [`day-one-review`](day-one-review.md)) to add scoped file boundaries, tiny receipts, dual-verdict integrity checks, and clean teardown on top of Antigravity's native board.

## Workflow stages

1. **Step 0: Defaults and collision check (`Coordinator`):** Read only the active `SKILL.md` entry file(s) (and run `swarm{action: "models"}` when pinning an explicit model; skip upfront reads of reference docs or prior review ledgers). On read-only cohorts and overlap-free scopes, start immediately with defaults (`flat` for inline tasks, staged `layered` waves for manifests with leads, coordinator model, `inherit`, `--prune`, and an Integrity Audit) so runs do not pause on a questionnaire and work in non-interactive `agy -p` sessions. Call `ask_question` **only** when `squad_planner` reports writable `siblingOverlaps` under `workspaceIsolation: "inherit"`, destructive state is unclear, or the user asks to customize run settings.
2. **Stage 1: Staged wave launch & `swarm_pane` (`Coordinator` -> `Specialists` -> `Leads`, + optional `monitor`):** Call `squad_planner` (`outPath`) or `agy-squad plan --out scratch/plan.json` to compile `swarmAdd` payloads, write `swarmPane` to `<appDataDir>/brain/<convId>/.system_generated/swarm/plan.json` to populate the Swarm UI Overview (`swarm_pane` replaces spawning a separate narrator worker), launch **Wave 1 (`specialists`)** via `swarm{action: "add"}`, emit verbatim `open_board` on its own line on launch turns (and on resume turns or when asked while active), and park quiet turns with `swarm_wait` (no `schedule` polling timers; workers skip Turn-1 `read_board` since Step 1 already holds their brief). In layered cohorts, spawn **Wave 2 (`leads`)** *after* squad specialist `READY` receipts arrive so domain leads read specialist report files directly instead of pre-reading source files.
3. **Stage 2: Slot reports, batch digest & Wave-3 integrity audit:** Each specialist writes evidence to `scratch/agy-squad/squad-<id>/specialist-<N>/report.md` and posts one single-line `<= 500` UTF-8 byte pointer (`@coordinator READY <slot> -- <observation>`, appending `wt=<abs-worktree-root>` under `share`/`branch`, accepting optional leading `@mention` + `[done]` prefixes and spaced ASCII ` - ` or ` -- ` alongside Unicode `U+2014`) on the board. In flat mode, the coordinator spot-checks cited `file:line` claims and writes `lead/report.md` (`Content Verdict: PASS | FAIL | BLOCKED`). The coordinator collects isolated slots (`agy-squad collect --plan scratch/plan.json --handoffs scratch/handoffs.json`) and runs `agy-squad bundle-init --plan scratch/plan.json --all-squads --handoffs scratch/handoffs.json --from-scope --digest --out-dir scratch/records` (which enforces content verdicts and emits digest-bound `auditSwarmAdd` briefs). Unless `--no-integrity` is set, **Wave 3 (`audit-<id>`)** audits execution traces in one batch pass (reading native `~/.gemini/antigravity*/brain/<id>/.system_generated/logs/transcript.jsonl` and `transcript_full.jsonl` directly standalone, or using `agy-context transcript` CLI calls when optional `Agy-Context-Saver` `2.1.2+` is installed, where transcript access defaults to `OPEN` and operators can opt into `[agy-transcript-access: allow|deny|self-only]` on line 1 of worker prompts or via `agy-context transcript access`) to emit standalone lines `Target Squad: <id>`, `Evidence Digest: <64-hex>`, and `Integrity Verdict: CLEAN | INTEGRITY VIOLATION`.
4. **Stage 3: Finalize, synthesize deliverable, prune, resume, or close:** Run `agy-squad finalize scratch/records/*.json [--strict-citations]` **without `--prune`** first (or when planned with `--no-integrity`, run `agy-squad finalize scratch/records/*.json --allow-unaudited [--strict-citations]`) so verified bundle SHA-256 hashes are ready while loose specialist reports remain readable on disk. Next, synthesize all verified `lead/report.md` outputs into one complete user-facing deliverable (or single-pass durable ledger) using the verified bundle hashes: in layered mode, open raw `specialist-N/report.md` only when `citations.uncarriedUrls` is non-empty, a verdict is non-`PASS`, or specific raw evidence is needed; in flat mode, synthesize directly from `specialist-N/report.md`. Finally, if report retention is `--prune`, run `agy-squad prune --records <record.json>=<accepted-sha256>... --clean-records` (or `<bundle.sources.json>=<sha256>...`); single-step `finalize --prune` remains available when no bundle hash needs to be embedded before pruning. Lead the final response with the deliverable and keep verdicts, bundle SHA-256 digests, prune counts, and runtime closure in a compact verification footer rather than returning governance telemetry alone, skipping duplicate closeout test reruns on read-only runs when `git status` is clean on the already-tested `HEAD`. Post `[done] <summary>` (no `@`) before pausing with waiting workers or closing so `monitor`'s `*/3` cron cancels cleanly. Resuming a paused swarm cascades top-down (`coordinator -> leads -> workers` in layered mode, or `coordinator -> workers` in flat mode) using a plain resume prompt (`resume your assigned work from where you left off`) and re-emits verbatim `open_board` on its own line on the resume turn (and when asked while active). On close, kill all workers plus `monitor` (`swarm{action: "kill"}`) and complete the [four-check runtime closure gate](../roles-and-workflows.md#3-runtime-closure-checklist-and-hook-boundary).
