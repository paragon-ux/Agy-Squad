# `day-one-review`: Cold First-Time-User Launch Audit & Remediation

Use `day-one-review` when auditing a repository from the perspective of a cold Day-1 developer installing and using it publicly tomorrow, then remediating confirmed findings and running cumulative follow-up reviews without digression.

- **Source specification:** [`.agents/skills/day-one-review/SKILL.md`](https://github.com/paragon-ux/Agy-Squad/blob/main/.agents/skills/day-one-review/SKILL.md)
- **Protocol reference:** [`day-one-protocol.md`](https://github.com/paragon-ux/Agy-Squad/blob/main/.agents/skills/day-one-review/references/day-one-protocol.md)
- **Governing standard:** [PR Review Standard v1.5.0](https://github.com/paragon-ux/Agy-Squad/blob/main/.agents/skills/pr-review/references/pr-review-standard.md)
- **Canonical role map & closure gate:** [Roles, skill workflows, and runtime closure](../roles-and-workflows.md)

## Execution defaults vs. explicit `/swarm` opt-in

- **Default (no `/swarm`):** Runs via direct `invoke_subagent` or single-agent execution to stay focused and avoid `/swarm` board overhead.
- **Explicit `/swarm` opt-in:** Only when the user explicitly asks for `/swarm`, pair with [`swarm-governance`](swarm-governance.md) using a **flat `/swarm`** compiled via `squad_planner` (`agy-squad plan --topology flat --read-only`), split into category-scoped read-only specialists tailored to the target repository plus **one flat Integrity Auditor (`audit-<id>`)** (structurally matching flat `self-diagnosis`, generalized for any target repository).

## Exact 4-stage workflow

1. **Stage 1: Cadence intake & `scratch/` audit anchor:** Before launching `r1`, ask the user strictly which review cadence they want without asking for or injecting bug hypotheses:
   - **Single-round cold audit (`r1` only):** read-only report and ship verdict, then stop.
   - **Multi-round (`r1` -> remediate -> `r2` cumulative):** iterate until the target ship verdict passes.
   - **Full public-launch gate (`r1` -> remediate -> `r2` -> unanchored live `raw-final`):** adds a fresh unanchored consumer live trial before merge or tag.
   - **Target stop verdict (multi-round or full gate):** confirm whether remediation stops at `SHIP NOW` (`0` open P0-P3) or `SHIP WITH MINOR POLISH` (`0` P0/P1/SEC and `<= 2` non-SEC P2/P3 polish items).
   Anchor all review files under `scratch/day-one-review/` (or a user-designated path), confirm `.gitignore` and release-tarball exclusion so audit artifacts never ship accidentally (use `docs/reviews/` only if explicitly requested), and pin branch, `HEAD` SHA, dirty delta, and runtime environment.
2. **Stage 2: Raw, unguided initial review (`r1`) with live consumer install:** Enforces a strict **Anti-Anchoring Rule** (putting `[agy-transcript-access: self-only]` or `deny` on line 1 of `r1` and `raw-final` subagent prompts whenever `Agy-Context-Saver` is installed, keeping cross-session transcripts isolated while letting long audits query their own post-compaction transcript). On `r1`, do **not** read prior review ledgers (`docs/reviews/*`), internal planning docs (`docs/plans/*`), `git log`, PR self-claims, or maintainer hypotheses before packing the release artifact, installing it into a disposable consumer project (normal + `--ignore-scripts` where applicable), compiling public types strictly (`skipLibCheck: false` for TypeScript SDKs), and walking the target repository live from the outside in (for governance or transcript plugins, run synthetic `.system_generated` consumer checks via hermetic test scripts rather than inline shell literals that trip active host hooks):
   - First 60 seconds (`README`, diagrams/jargon, Quickstart, package/site metadata)
   - Clean install, setup, upgrade, and rollback (fresh host, `--ignore-scripts`, off-`PATH`, cross-OS, strict public typecheck)
   - Everyday usage inside an unrelated user project (zero checkout assumptions, live CLI/SDK/MCP dogfooding, error clarity, friction)
   - Security and trust boundaries (`4.11 SEC`: execution surface, downloads/checksums, permissions, secret hygiene, `timeout 5`-bounded linear-time regex / ReDoS probes, least-privilege CI workflow `permissions:` / `concurrency:`, uninstall cleanliness)
   - Packaging, CI, and release pipeline (tarball allowlist, exact artifact publish, multi-OS CI)
   Write `scratch/day-one-review/day-one-review-r1.md` conforming to Standard `v1.5.0` Sections 1-8 (`ARCH`..`DEP`, `SEC`), the **Cold Day-1 User-Journey Trace Matrix**, and the explicit **4-tier Ship Verdict**:
   - **`SHIP NOW`**: `0` open P0/P1/P2/P3 actionable in-repo defects (only tracked Section 8 residuals, upstream deferrals, or informational notes remain, if any).
   - **`SHIP WITH MINOR POLISH`**: `0` P0/P1/SEC blockers and at most `<= 2` small, localized P2/P3 polish items with zero broken consumer install, compile, SDK, or core-command contracts.
   - **`FIX BEFORE RELEASE`**: `0` P0/P1/SEC blockers, but **`>= 3` open P2/P3 items** or any P2 breaking consumer compilation, installation, or core documented workflows (under Stage 3, all concrete in-repo P0-P3 defects are fixed automatically to reach the target stop verdict).
   - **`HOLD BEFORE PUBLIC RELEASE`**: Any open P0/P1 blocker, any unresolved `SEC` vulnerability, or any unreviewed material category.
3. **Stage 3: Auto-fix P0-P3, ask only on Section 8 residuals & selective resume:** Keep code edits separate from review passes and checkpoint clean git state. In a Day-1 launch review, **P3 findings are concrete user-facing in-repo defects and are remediated automatically alongside P0-P2, no questions asked.** Reserve **Section 8 (`Post-Remediation Residuals & Deferred Dispositions`)** as the decision gate where the agent asks the user before acting or deferring: external/upstream dependencies, intentional behavior/contract trade-offs that could break existing suites or users, policy-gated files (such as benchmark definitions), and subjective suggestions.
   - **2-round escalation stop-rule:** If any finding ID remains `Open` after 2 remediation rounds (still `Open` in `r3`), stop heuristic patching and apply an architectural or structural replacement before launching the next verification round.
   - **CPU/daemon & live-hook serialization rule:** Default Stage 3 remediation to a single coding subagent whenever the target repository uses native indexers, local daemons, database locks, or live symlinked plugin/hook files (reserving parallel coding subagents for lightweight, independent modules).
   - **Pre-push checks:** Run targeted suites + `timeout 5`-bounded adversarial probes on narrow intermediate `r2+` deltas, and run the full local gate (full tests, strict consumer typecheck, preflight, packaging, docs/lint, `timeout 5`-bounded ReDoS probes, and least-privilege CI workflow `permissions:` / `concurrency:`) on the `SHIP NOW` pass or whenever shared/cross-cutting files change.
   - **Interruption rule:** If remediation is interrupted (rate limit, timeout, disconnect, pause), inspect `manage_subagents(Action='list')` and **resume ONLY the interrupted subagent(s)**. Never send unsolicited messages to healthy running workers and never spawn duplicate replacement subagents over existing work. Only if a subagent permanently died mid-edit, run a read-only recovery audit first (git diff + worker transcript including tool calls) before finishing only the unremediated remainder.
4. **Stage 4: Cumulative follow-up reviews (`r2`, `r3`, ...) & unanchored live `raw-final`:** Follow-up reviews build directly on `r1` inside the same audit directory (`day-one-review-r2.md` linking `Prior review: day-one-review-r1.md`), keeping previously `Closed` P1/P2 findings as compact 1-line rows in Section 7's Closure Table (referencing `r<N>` for their full 10-field card) while reserving full 10-field cards for findings opened, re-opened, or closed in the current round. On narrow intermediate deltas (1-2 open IDs without shared-file edits), `r2+` runs targeted test suites and `timeout 5` probes, reserving a single full-gate confirmation for `SHIP NOW`. Under the full public-launch gate (or when requested), run one fresh unanchored live consumer trial (`day-one-review-raw-final.md` with `[agy-transcript-access: self-only]` or `deny` when `Agy-Context-Saver` is installed) before merging or tagging.
